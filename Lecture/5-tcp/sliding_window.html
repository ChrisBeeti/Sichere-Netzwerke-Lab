Prinzip
Sender darf mehrere Pakete senden, ohne auf jedes ACK zu warten — Anzahl = Fenstergröße.
Effizienz
Ohne Sliding Window: Senden → Warten → Senden … Schlechte Leitungsauslastung bei hoher Latenz.
Fenster verschiebt sich
Nach ACK für Paket N rückt das Fenster um 1 nach rechts — Paket N+WS wird freigegeben.
Timer
Läuft nur für Pakete im Fenster. Kein ACK innerhalb der Zeit → Retransmission.

Go-Back-N
Nach Verlust eines Pakets werden alle nachfolgenden Pakete erneut gesendet — ab dem verlorenen Paket.
ACK-Verhalten
Der Empfänger sendet für alle Pakete nach dem verlorenen Paket denselben ACK zurück: AckNr = SeqNr des verlorenen Pakets.
Selective Repeat
Alternative: Nur das verlorene Paket erneut senden (SACK-Option im TCP-Header). Effizienter, aber komplexere Pufferverwaltung.
Timer
Kein ACK innerhalb des Timeouts → Fenster wird zurückgesetzt, Retransmission ab verlorenem Paket.

Dynamische Fenstergröße
Jedes ACK enthält das aktuelle Receive Window (rwnd) des Empfängers — der Sender passt sein Fenster sofort an.
Window = 0
Wenn der Empfangspuffer voll ist, setzt der Empfänger rwnd = 0. Der Sender pausiert und wartet auf einen Window Update.
TCP-Header-Feld
Das Window-Feld im TCP-Header ist 16 Bit breit → max. 65.535 Byte (ohne Window Scale Option).
Zweck
Verhindert Empfangspufferüberlauf beim Empfänger — unabhängig vom Congestion Window (Netzüberlastung).
